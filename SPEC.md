# Build "Isle of Ants" Educational Simulation

**1. Project Scope & Architecture**
You are an expert web developer and educational software engineer. Your task is to build a web-based programming game called "Isle of Ants." The application must be deployed as a multi-file static site (HTML, CSS, JS) suitable for GitHub Pages.
* **Architecture:** The entire application must run client-side in the browser. **No backend server or Python kernel is permitted.**

**2. Tech Stack Requirements**
* **Frontend:** Standard HTML, CSS, and JavaScript.
* **Visualizer:** HTML5 `<canvas>` for rendering the game grid and overlays.
* **Python Execution:** **Skulpt** (JavaScript implementation of Python) to securely evaluate player-submitted code in the browser.
    * **Crucial Skulpt Config:** You must configure Skulpt to intercept `sys.stdout` so that any `print()` statements in the user's Python code are routed to the custom UI's Debug Panel, not the hidden browser developer console.
* **Integrated Editor:** **CodeMirror** configured for Python to provide syntax highlighting, line numbers, and basic indentation support.

**3. Application UI & Workflow**
* **Setup Panel:**
    * Inputs to define Grid Size (e.g., 20x20) and Max Turns.
    * A "Players" section allowing the user to add 0, 1, or multiple players.
    * Each player entry must include a `Name` field and an embedded CodeMirror editor.
* **Code Editor (The LeetCode Pattern):**
    * The CodeMirror editor for each player must *only* accept the body of the `move` function.
    * The function signature (`def move(nearest_ant, nearest_anteater, nearest_shore, current_turn):`) must be displayed as read-only, statically styled HTML text immediately above the CodeMirror input area to visually frame the student's workspace.
* **Simulation Interface:**
    * An HTML5 `<canvas>` rendering the grid, water boundaries, ants (simple visual markers), and anteaters (distinct colors/icons labeled with player names).
    * **Playback Controls:** `[Validate Code]`, `[Start]`, `[Step]` (advances exactly one turn), `[Stop/Reset]`, and a `[Speed Control]` slider.
    * **Dev Mode Toggle:** A checkbox for "Show Vectors" (details below).
    * A live scoreboard tracking ants eaten by each player.
    * **Debug Output Panel:** A dedicated text area per player that displays their intercepted `print()` outputs as well as syntax/runtime errors with line numbers.

**4. The Player API & Code Wrapping**
Students will write the logic for their anteater using standard Python.
* **Code Wrapping & Auto-Imports:** Before passing a player's code to Skulpt for evaluation, the JavaScript engine must dynamically construct the final Python script. The JS engine must prepend `import math\nimport random\n`, append the exact `def move(...)` signature, and dynamically indent the student's submitted code block by 4 spaces to sit properly inside the function body.
* **Inputs:**
    * `nearest_ant`, `nearest_anteater`, `nearest_shore`: Passed as 2-tuples of integers representing relative vectors (distance and direction) to the closest respective entity. For example, `(-2, 1)` means the target is 2 spaces left and 1 space down.
    * `current_turn`: Passed as an integer starting at `1` and incrementing each turn.
* **Absence of Entities (Edge Cases):** If there are 0 ants remaining, `nearest_ant` must be passed as `None`. If playing solo, `nearest_anteater` must be passed as `None`. Ensure the JS-to-Skulpt bridge correctly translates `null/undefined` to Python's `None`.
* **Output:** The function must return a 2-tuple `(dx, dy)` representing the desired move. Values for `dx` and `dy` are strictly limited to `-1`, `0`, or `1`. Diagonal moves are allowed.

**5. Simulation Engine & Rendering**
**Determinism & Randomness:**
The simulation must remain 100% deterministic per run so students can accurately debug using the `[Step]` button.
* When `[Start]` is clicked, the JavaScript engine must establish a fixed seed.
* This seed must dictate the random behavior of the ants, the randomized turn order of the anteaters, AND the random numbers generated by any player's Python script via Skulpt's `random` module. Re-running the simulation without changing code/settings must produce the exact same outcome.

**Distance & Targeting (Tie-Breaking):** When calculating `nearest_X`, use **Euclidean distance** ($\sqrt{dx^2 + dy^2}$).
* **Tie-Breaker:** If multiple targets are equidistant, break the tie deterministically using grid "reading order." Select the target with the lowest Y coordinate (closest to top). If still tied, select the target with the lowest X coordinate (closest to left).

**Dev Mode ("Show Vectors" Toggle):**
When enabled, the `<canvas>` should overlay a visual aid for the current turn: draw a faint line from each anteater to its `nearest_ant` and `nearest_shore`, and float the literal tuple text (e.g., `(-2, 1)`) next to the line.

**Turn Phase Logic (Iterating up to Max Turns):**
1.  **Ant Phase:** All ants calculate and execute a random move `(dx, dy)` limited to `{-1, 0, 1}`. Moves that would take an ant off the island grid are canceled (the ant stays put).
2.  **Anteater Phase:** * Execution order of anteaters must be **randomized** every turn.
    * Calculate input vectors based on current board state and execute their Skulpt function.
    * **Safety & Errors:** Skulpt must have a timeout (e.g., 200ms) to prevent infinite loops. If the script times out, throws a runtime error, or returns an invalid data type/range, the move defaults to `(0, 0)` and the error is logged to the player's Debug Output.
    * **Collisions:** If the returned move places the anteater off the grid (into the shore), the move is invalidated, and the anteater remains stationary.
    * **Eating:** After all movements are resolved, if an anteater shares a coordinate with one or more ants, those ants are removed from the simulation, and the anteater's score increases by 1 for each ant consumed.
3.  **End Condition:** The simulation ends when Max Turns are reached or 0 ants remain. The player with the highest score wins. If multiple players share the highest score, the UI should declare a Draw and list the co-winners.
